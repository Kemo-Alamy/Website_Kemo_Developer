# KEMO DEVELOPER PRO — دليل الإعداد

## ما الذي يتضمنه المشروع؟
- تصميم متجاوب مستوحى من ترتيب وأسلوب صفحة المرجع: واجهة Hero، أقسام متعددة، بطاقات مشاريع/تطبيقات، تصنيفات، حركات ظهور، ووضع فاتح/داكن.
- إنشاء حساب بالبريد وكلمة المرور، تسجيل الدخول، تسجيل الخروج، واستعادة كلمة المرور.
- قائمة تطبيقات من Cloud Firestore مع بحث وتصنيف.
- لوحة أدمن لا تظهر إلا للحساب الذي أُضيف UID الخاص به يدويًا في مجموعة `admins`.
- رفع غلاف التطبيق وملف APK/AAB/ZIP/XAPK/APKS إلى Firebase Storage، وتعديل وحذف التطبيقات.
- قواعد Firestore وStorage مرفقة.

## مهم جدًا بخصوص التخزين والتكلفة
ابتداءً من 3 فبراير 2026، يتطلب Cloud Storage for Firebase تفعيل خطة Blaze وربط حساب فوترة حتى للمشاريع الجديدة. توجد حصص استخدام بلا تكلفة على Blaze، لكن تجاوز الحصة قد يؤدي إلى رسوم. لا تفعّل الفوترة أو تضف وسيلة دفع بنفسك؛ اطلب من ولي أمرك مراجعة ذلك أولًا. إذا أردت البقاء على Spark بدون فوترة، يمكن تشغيل الحسابات وقاعدة البيانات لكن رفع ملفات APK من لوحة الموقع إلى Firebase Storage لن يعمل. راجع:
https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024

## 1) إنشاء مشروع Firebase
1. افتح https://console.firebase.google.com/ وأنشئ مشروعًا.
2. من Project settings > General > Your apps أضف تطبيق Web.
3. انسخ إعدادات Firebase العامة إلى `firebase-config.js`.
4. قيمة `storageBucket` يجب أن تكون بالضبط كما تظهر في إعدادات Firebase. المشاريع الحديثة غالبًا تنتهي بـ `.firebasestorage.app`.
5. Authentication > Sign-in method: فعّل Email/Password.
6. Firestore Database: أنشئ قاعدة البيانات، ثم من Rules انشر محتوى `firestore.rules`.

## 2) إنشاء Storage (اختياري لرفع الملفات)
1. راجع ملاحظة الفوترة أعلاه أولًا.
2. إذا كان مشروعك مهيأً ومصرحًا باستخدام Storage، افتح Storage > Get started.
3. من Rules انشر محتوى `storage.rules`.
4. إذا لم تفعّل Storage، يمكن إبقاء الموقع على قاعدة البيانات والتسجيل فقط، لكن رفع الملفات لن يعمل.

## 3) إنشاء حساب الأدمن
1. افتح الموقع بعد إضافة إعدادات Firebase.
2. أنشئ حسابك من زر «إنشاء حساب».
3. من Firebase Console > Authentication > Users انسخ User UID للحساب الذي أنشأته.
4. افتح Firestore > Data > Start collection.
5. اسم المجموعة: `admins`
6. اسم المستند (Document ID): ألصق UID كما هو.
7. أضف الحقل `role` من النوع `string` والقيمة `admin`.
8. احفظ، ثم سجّل الخروج والدخول مجددًا. ستظهر لوحة إدارة المحتوى.

**لا** تضف مستند `admins` لأي مستخدم آخر. قواعد الأمان تمنع الموقع من إنشاء أو تعديل مستندات الأدمن.

## 4) تشغيل الموقع محليًا
المشروع Static ولا يحتاج عملية build:
- افتح المجلد في VS Code.
- شغّل `index.html` باستخدام إضافة Live Server، أو ارفع الملفات إلى GitHub Pages.
- لا تفتح الملف مباشرة بنظام `file://` لأن وحدات JavaScript قد لا تعمل.

## 5) النشر على GitHub Pages
1. ارفع محتويات المجلد إلى مستودع GitHub.
2. Settings > Pages > Deploy from a branch.
3. اختر الفرع `main` والمجلد `/(root)`.
4. أضف نطاق GitHub Pages في Firebase Authentication > Settings > Authorized domains.

## 6) رفع تطبيق جديد
من لوحة الأدمن:
- اكتب الاسم والوصف والتصنيف والإصدار.
- اختر صورة غلاف اختيارية.
- اختر ملف التطبيق (حتى 200MB في واجهة المشروع).
- اضغط «نشر التطبيق».
يمكن تعديل التطبيق أو حذفه من قائمة الإدارة.

## تنبيهات أمنية
- لا تضع كلمة مرور في ملفات الموقع أو GitHub.
- لا تضع Service Account JSON أو private key في `firebase-config.js`.
- `firebase-config.js` يحتوي إعدادات Web العامة فقط؛ الحماية الفعلية من قواعد Firestore وStorage.
- اختبر الموقع بحساب مستخدم عادي قبل إتاحته للزوار.
- لا ترفع إلا ملفات تملك حق توزيعها، وتحقق من سلامة الملفات قبل نشرها.
